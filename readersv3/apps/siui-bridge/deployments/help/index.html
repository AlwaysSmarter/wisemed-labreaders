CNAS - validare paraclinice 72h

Utilitarul trimite imediat validarea prin validateReport / PARA / RQ_PARA_SRV. Nu așteaptă 72 de ore.

Configurare

  1. Configurează WiseMED și autentifică-te.
  2. Deschide Setări → CNAS, completează utilizatorul CNAS și apasă Reîncarcă certificatele.
  3. Selectează certificatul tokenului și salvează. Nu se exportă fișiere CER.
  4. Introdu seria de licență CNAS în câmpul mascat din Setări. Se salvează în configurație, fără fișier separat. Câmpul gol păstrează valoarea existentă. Pe Mac poți salva și înainte de selectarea tokenului.
  5. Configurează WSM în Debug → WSS. HTTP/HTTPS și logurile folosesc opțiunile comune.

HTTPS local

Pe macOS, acceptă autorizarea Keychain pentru WiseMED Local Root CA. Dacă importul este refuzat, deschide deployments/tls/wisemed-local-root-ca.pem în Keychain Access și setează Always Trust. Repornește browserul. Pe Windows se folosește magazinul Root; Linux cere drepturi root pentru instalarea încrederii. Erorile de import apar în log.

Verificări fără raportare

Test local fără CNAS verifică pe Mac un răspuns fictiv. Pentru Windows cu token: Testează autentificarea OCSP verifică numai sesiunea; Verificare calitate de asigurat primește CNP și dată; Descarcă personalizare PARA primește intervalul și descarcă fișierul furnizorului. Fiecare apel real obține automat sesiunea OCSP. Aceste butoane nu trimit servicii la validare.

Actualizări și conexiune

Folosește Server și actualizări pentru configurarea update-ului și Verifică actualizări pentru verificare manuală. Actualizările folosesc cheia WiseMED. Portul SIUI este explicit în formular (443 implicit, 444 unde este necesar). La eroarea Windows 12175, mesajul include cauza TLS; un certificat expirat al serverului CNAS necesită remediere la endpoint.

Validare

Trimite XML PIAS complet și un ID unic de operație, prin formularul de test sau POST /api/siui/validations. Prin WSM folosește aceeași rută în api.request. Consultă jobul la GET /api/siui/validations/{id}.

completed înseamnă răspuns primit. Verifică result.validated, starea și erorile fiecărui AppID. unknown nu se retrimite automat. Păstrează AppID-ul serviciului la corecții.

Serviciu și token

Pe Windows: -installservice, -headless, -reconfigure, -showlog, -version. Configurația este în deployments/config.yaml. Contul serviciului trebuie să aibă acces la token. Dacă driverul cere dialog PIN interactiv, folosește sesiunea utilizatorului sau modul noninteractiv al driverului.

Detaliile API și exemplele sunt în documentația aplicației. Testarea locală nu înlocuiește verificarea pe Windows cu tokenul și contul CNAS real.
