## Arhitectură
Go modular monolith (net/http sau router minimal), PostgreSQL cu pgvector, migrații SQL versionate, Dockerfile multi-stage și compose pentru app+db; Redis numai dacă este justificat. Go servește API-ul și frontend-ul Vue compilat prin go:embed; fără Node runtime în producție. Health/readiness, graceful shutdown, timeouts, limits, retries și audit. Adaptoare opționale WiseMED API, WSM, Odoo și alte HIS; fără ele aplicația standalone trebuie să funcționeze.

## Web GUI — produs premium
Vue 3 + TypeScript + PrimeVue + TipTap, responsive mobile-first, temă coerentă premium, light/dark, navigare clară. Ecrane funcționale: login și cont, dashboard, medici/organizații/roluri, Specialty Packs, șabloane, editor WYSIWYG, preview și test cu transcript sintetic, sesiuni, rezultate, feedback/memorie, conectori, chei/configurație AI, usage/costuri, audit și setări. Nu afișa secrete în clar. Folosește componente reutilizabile, formulare cu validare, empty/loading/error states, accesibilitate și layout pentru tabletă.

## Editorul inteligent

Două perspective: document vizibil și câmpuri structurate inclusiv invizibile. Template local fields, semantic tags opționale, mapping semantic la model canonic și mapping tehnic separat pe conector. # WiseMED AI — Contract comun între proiecte
Scop: asistent de documentare clinică, NU motor de diagnostic. Nu inventa observații, măsurători, tratamente ori rezultate. Orice informație clinică extrasă trebuie să aibă proveniență în transcriere sau context autorizat. Lipsa informației ≠ rezultat normal. Medicii revizuiesc și aprobă rezultatele înainte de persistarea în HIS.
Arhitectură: Flutter mobil ↔ Go API ↔ PostgreSQL/pgvector; UI administrare Vue 3/TypeScript/PrimeVue/TipTap, compilat și inclus prin go:embed. WiseMED, WSM, Odoo și alte HIS sunt integrări OPȚIONALE. Standalone funcționează complet fără ele. WSM este transport opțional, nu infrastructură obligatorie. Backend Go este dezvoltat în ecosistemul WiseMED Lab Readers, cu respectarea convențiilor reale constatate în repository, fără a presupune API-uri sau structuri inexistente.
Produs: medicul selectează specialitatea și contextul (ambulatoriu, internare, ambele), primește Specialty Packs cu șabloane predefinite și poate crea sau personaliza șabloane. Placeholder-ele sunt locale șablonului, cu semantică opțională și mapări tehnice externe. Editor WYSIWYG cu câmpuri obligatorii/opționale, tipuri, unități, secțiuni condiționale și repetabile, fragmente normale/patologice, variabile globale de context (pacient/medic), versiuni imutabile la publicare. Șabloanele produc HTML, JSON clinic structurat și/sau acțiuni PROPUSE; aplicația externă controlează procesele de business.
Sesiuni: standalone sau context lansat de HIS (buton, QR temporar, listă). Un workspace poate include consultație, EKG, ecografie și măsurători. Contextul și destinația sunt autorizate; nu confunda menționarea unei proceduri cu efectuarea sa. Patient Briefing este add-on ON DEMAND, exclusiv la apăsarea «Informare», nu automat. Stocurile și consumurile rămân în HIS/Odoo; AI poate returna informații structurate, fără scăderi de stoc sau prescripții automate.
Memorie: preferințe și feedback aprobate per medic/organizație, portabile conform drepturilor; PostgreSQL + pgvector pentru recuperare semantică selectivă, nu copie generală a dosarelor pacienților. Date sensibile: minimizare, acces RBAC/tenant, criptare în tranzit și la stocare, audit, retenție configurabilă, ștergere/export, fără date reale în teste, fără training implicit pe date clinice. Verifică cerințele GDPR și reglementările aplicabile înainte de producție.
Contract API versionat: POST /v1/sessions, GET /v1/sessions/{id}, POST /v1/sessions/{id}/transcript-chunks, GET /v1/sessions/{id}/events (SSE sau WS documentat), POST /v1/sessions/{id}/finalize, GET /v1/sessions/{id}/result, POST /v1/sessions/{id}/approve, plus auth, templates, specialty-packs, profile, integrations. Definiți împreună OpenAPI 3.1 și exemple fixture; adaptați căile dacă repository-ul existent are convenții proprii. Fiecare chunk: id, sequence, revision, is_final, timestamp, text; suportă duplicate, retransmisii, corectarea ipotezelor STT, reconectare și idempotency. Result: session_id, schema_version, template_version, structured_data, rendered_html, missing_fields, evidence, warnings, status; never auto-save without approval. Nu trimite PHI în loguri.
Calitate: teste unitare, integrare, contract, UI și e2e; lint, format, build, migrații, README, .env.example, Docker Compose pentru dev, health checks, observabilitate, securitate. Rulează testele disponibile și corectează erorile până la trecere; nu pretinde că ai testat lucruri care nu au putut fi executate. Dacă lipsesc secrete/servicii, folosește mock-uri și documentează clar blocajul. Nu suprascrie componente existente fără audit și backup. Nu inventa endpoint-uri WiseMED/WSM; inspectează repository-ul și izolează necunoscutele în adaptoare.
